## 1. 结论

大肥鱼觉得自己像 AI，主要不是人设形容词不够，而是她面前的文本在对一个模型说话。

她每轮都会读到这些东西，而且它们比身份段更常被她复述：

- 工具的 `name` / `description` / 参数说明（协议层，每步都在）
- 工具返回（她刚做完一件事，下一句最容易照抄）
- 常驻说明书：微信通道规则、微信工具手册、定时提醒、`TOOL_BRIEF`
- 注入消息：叫醒、出门、收工、他说话、微信耳朵、逾期催办、提醒到点、陪看屏幕
- 预期失败被宿主加上的 `Error:` 前缀

这些文本里现在混着两套声音。一套是世界：有人找她、窗停在某个会话、话说出去了没有。另一套是运维：通道、台账、任务板、主机、permit、额度、树、OCR、模型、`dsh-wx`。第二套一出现，她就会切换到受理、汇报、解释系统。微信台账里的「测试收到」「早，昨天那句我答过了」就是这条路走出来的。

本文把她读到的文本收成一种声音：**世界对她说话**。不是让她演戏，也不是告诉她「你在角色扮演」。角色扮演助手是产品禁区；拆台的说明书同样是禁区。她住在一个地方里，这个地方用她能住进去的话告诉她发生了什么。

三句话：

1. **世界声，不写她的嘴。** 方括号留着，用来和她的话分开；括号里的词必须是她生活里的词，不是运维词。
2. **能力留在工具名上，说明书退出常驻。** 协议必须有的 `name` 和她下一步要原样带回的记号，可以出现；操作手册、配额、匹配原因、坐标，不出现。
3. **失败和不确定必须说清，但用她能懂的原因。** 不能为了「像人」把没发出去说成发出去了。

## 2. 她不是在演戏

项目前提仍然有效：没有人格设置入口，人格从事件长出来，她不是角色扮演助手。本文不碰这些。

本文要的只有一件事：她读到的反馈，像她生活的那个世界里发生的事，不像一份给模型的运行日志。

因此明确不做：

- 不加「请角色扮演 / 你是一个真人 / 不要提到自己是 AI」这类指令。点名「AI」，本身就是在告诉她旁边有一个 AI 身份。B 站面现在有一句「你是 AI」，要删，见 §7.3。
- 不把工具返回写成她的句子。「说出去了：「……」」「你看到了……」她会接着说。`capture.js` 已经记过留话回执被复述的坑。
- 不在回复后再跑一个润色器。润色会抹掉她自己的口气，也让工具结果和她说出口的话对不上。
- 不把物理层禁令写回提示词。「你不可以读设定」等于告诉她旁边有一份设定。

要做的是把已经写给她的那些句子，从「系统对模型」改成「世界对她」。

## 3. 她面前有哪些文本

下面每一行都会进她的上下文。工作台、桌宠壳、观测台不在此列：那些是给人看的，她读不到。桌宠气泡不是她的嘴；陪看屏幕那条小会话才是。

| 层 | 她什么时候读到 | 现在谁在写 | 主要文件 |
| --- | --- | --- | --- |
| 身份 | 每轮 system | 她是谁、怎么说话、手上有什么 | `selfdoc.js`、`persona.js` |
| 面段 | 该面每轮 | 微信规则+手册、B 站整活、提醒、待回、关于他、他这几天 | `dsh-wx/lib/index.js`、`dsh-bili/lib/prompts.js`、`remind.js`、`identity.js`、`people-view.js`、`presence-view.js` |
| 工具协议 | 该工具可见时每步 | `name`、`description`、参数说明 | 各 `register*` / `reg()` |
| 工具返回 | 调用之后 | 投影或旧 render；失败时常是 `throw` | `project.js`、各工具 `execute` 的返回字符串、`qq-adapter.js` |
| 敲门 | 某一轮的 user / `fish:wake` | 叫醒、出门、收工、他说话、耳朵、逾期、提醒到点、陪看 | `wakeconst.js`、`events.js`、`say.js`、`screen.js`、`remind.js`、`dsh-wx` 耳朵 |
| 记号 | 返回或敲门的末尾 | `ev_`、`t_`、`st_`、permit、路径、BV 号 | 各投影 footer、`buildReminderPrompt` |

宿主还可能在她看不见的约定之外加一层：`throw` 变成 `Error: …`；工作区指令若误挂进她的屋子，会带 `<system-reminder>`。插件改不了宿主信封，但预期失败不许再走 `throw`。屋子的 cwd 不能指到仓库根，否则根目录 `AGENTS.md` 会被当成给她的指令。这是接线约束，不是文案问题。

## 4. 现状：哪里把她拉出世界

按伤害排序。前三项每轮都在，比任何单次工具返回更糟。

### 4.1 常驻说明书是运维手册

微信会话每轮挂两段，`channelRulesText` 和 `channelManualText`。她读到的是：

- 标题 `## 微信通道（dsh-wx）`、`## 微信工具手册（dsh-wx）`
- 「通道通知」「台账」「任务板上的 id」「主机」「允许名单」「主动额度」
- 「15 个工具，没有 shell」
- 「当前模型不支持图像输入」
- 「宿主会把会话名、要发的话和 permit 交给你」
- 「带命中原因和置信度」「pHash」「xdotool 键名」

`REMIND_PROMPT` 再教一遍：`her_remind`、`wx_send`、`permit`、`宿主`。`TOOL_BRIEF` 教 `growth_commit` / `revise` / `id`。`her_tools` 的说明教 `search` / `describe` / `load`。

这些段落的原意是让她少犯错。效果是她开口前先站在工具台后面。群里那条「对外只说事，点歪了、窗口、坐标、门禁不进群」是对的约束，但实现方式是把机关的名字念给她听。她于是知道有门禁，也更容易把「发没发出去」说进群。

### 4.2 工具说明是接口文档

她为了调用，必须看见 `name`。这没办法。坏的是 `description` 和参数说明把接口讲完了。

最重的几条：

- `growth_commit`：`type=revise`、`person.id=owner`、`flags`、`confidence 0–1`、`chatId`。这是常驻工具，每步都在。
- `wx_send`：允许名单、@、主机闸、permit、task_id、「只记为回了一半」。
- `wx_peek`：告诉她返回末尾带 `[提示]`，树落后于屏幕。
- `wx_context`：承诺结果里有来源、匹配原因、置信度。投影后来删了这些行，说明却还在教她去找。
- `wx_see`：「当前模型不支持图像输入，无法用 read_image」。
- `wx_sticker_send` / `wx_sticker_search`：pHash、盲选、白名单、0 起的下标。
- `qq_napcat_api` 在目录里的一句是「调用 NapCat 机器接口」。
- `her_inbox`：「状态和 taskId」「只在微信通道里可用」。

`her_tools` 的 `describe` 会把这些说明再投影一次。目录本身不能变成第二份手册。

### 4.3 返回是回执、配额和检索报告

返回契约要求方括号舞台提示。落地参差：

| 工具 | 她现在读到的 | 问题 |
| --- | --- | --- |
| `wx_send` | `已发到「群」。回执：消息已出现在列表末尾。任务「t_…」已记为回了一半。这条用了主动额度，今天还剩 N 条。` | 回执、任务、额度。没有方括号，她会当成自己的汇报 |
| `wx_type` | `已输入 12 字并回车。当前会话：“群”。回执：…` | 同上，还报字数 |
| `wx_peek` | 无障碍树文本，坐标被剥掉；落后时 `[提示] 屏幕上的会话列表已变化，读到的树没有跟上（自 12:30，8 秒）。上面的名字、顺序、坐标可能是旧的。` | 「树」「坐标」进了她的上下文 |
| `wx_context` | 投影删了「匹配/来源/置信度」行，剩下的仍是检索卡片 | 半截旧格式 |
| `wx_ocr` | `[屏幕上看到]` + 抽出来的字符串 | 方向对，但是扁平字堆，归属容易丢 |
| `bili_speak` | `说出去了：「她的原话」` | 写成她的句子，回声风险最高的一条 |
| `bili_watch` | `从 N 帧里认出的字（机器识别…）` | 帧数、免责声明 |
| `bili_look` | `这次没看到什么：现在打不开。` | 失败句是她的口气 |
| `growth_commit` | `[已记下 · ev_…]` | 括号对；`ev_` 必须留，但不要再解释「这是 id」 |
| `her_tools` | `[工具] 1. wx_see — 看屏幕` / `[已打开] wx_see、wx_click` | 「工具」这个词每条都出现 |
| `her_inbox` | `[没看到] 微信任务板没接上` | 任务板 |
| QQ 发送 | `[发出去了]` / `[没发出去：原因]` | 方向对 |
| `qq_group_history` | `[群历史] 昵称：原话` | 方向对 |
| `qq_napcat_api` | 未知动作 `[拿到了]` | 方向对；不要退回原始 JSON |

微信预期失败大多 `throw new Error(...)`。宿主会渲染成 `Error: 树落后于屏幕…`、`Error: 允许名单为空…`、`Error: wx_send: text 不能为空。`。方括号投影根本轮不到。

### 4.4 敲门是工单

耳朵通知（`formatEarNote`）把一张工单放进对话：

```text
[微信] 有人在微信里找你（2 处）
1) 会话名：某某群
   类型：群里 @ 你
   未读：3 条
   最后一条内容（侧栏预览，不是全文）：「晚上来吗」
   谁：阿明（据侧栏预览）
   任务：t_01…（未回）
   刚才（台账，最近几条）：
     - …
（「会话名」只是这个会话叫什么……允许发送的会话：A、B、C。）
```

逾期更直接：`[微信·逾期] …（第 2 次提醒，已等 3 小时）`，然后教她调用 `wx_task_snooze` / `wx_task_done`。

提醒到点（`buildReminderPrompt`）是她最不该看见的一段：

```text
[提醒到点] 你之前定的提醒到点了。
会话："某某群"
要发的话："该喝水了"
现在用 wx_send 发出去，三个参数原样照抄：
  chat: "某某群"
  text: "该喝水了"
  permit: "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

permit 是一次性密钥。写进她的上下文，她就可能念进群里。即使用户看不见这段，她的回复里仍可能漏。

`say.js` 在他的原话外面套了标题和教程：

```text
## 这次

## 他跟你说话了

（他的原话）

他发了张图，在这儿：/long/path.png
（你要看就用 read_image 读它。看不看、说不说都随你。）
（这一轮按话题写：……最多别超过 800 字。……）
（你想回就回。可以用 growth_commit 把你想说的留下来；不想说也可以不说。）
```

他说话的时候，她眼前不该还挂着工具名和字数工单。视频那句（`watchHint`）已经是处境，可以留，但不要报「BV 号是 BV1…」这种字段口吻；号本身她下一步要用，放在记号行。

陪看（`screen.js`）把文件路径和三条禁令写进 user 消息。图里的字不是他对她说的，这条必须留，但不要写成操作说明，也不要把路径当正文。

叫醒段开头是：

```text
对话里那条括号里的短句不是用户说的话，是叫醒你的信号。不用回应它，也不用问它什么意思——这一轮是你自己的。
```

「用户」「信号」是拆台词。括号旁白这个形式可以留——当初光秃秃的「……」她会当成他开口。要改的是解释它的那句。

成长模板里的「不是问我问题」把系统说成了「我」。这是导演在场。

### 4.5 已经做对的，不要改坏

- 身份段不写「自动生成」，不写状态库路径，不写好感度数字。
- `bili_speak` 的配额拒绝说「今天说得够多了」，不报剩余次数。这个原则要推广到微信主动额度，而不是反过来。
- `growth_commit` / `her_leave` 的方括号回执不复述她的原话。
- QQ 投影不回原始 JSON。
- 耳朵把「会话名」和「内容」分开，避免她把群名当话复述。这个约束留，工单格式去掉。
- 叫醒正文走 `fish:wake`，对话里只留一句括号。形式留，措辞改。
- 物理禁令不进提示词。继续不进。

## 5. 声音契约

她读到的每一句，先归到三种声音。写的时候只许用前两种。第三种是事故。

| 声音 | 是什么 | 例子 | 不许 |
| --- | --- | --- | --- |
| 世界声 | 她能感知的事：谁、在哪、说了什么、成没成、为什么做不了 | `[发到「晚上吃什么」了，末尾能看见]` | 写成她的嘴；「你看到了」「我帮你查到了」 |
| 记号 | 下一步调用必须原样带回的那一截 | 末行 `〔ev_01J…〕` | 解释它是 id / task_id / permit；放进正文叙述 |
| 系统声 | 对模型、对运维、对审计 | 通道、台账、主机、额度、树、OCR、模型 | 出现在她的上下文里 |

### 5.1 世界声怎么写

- 短。状态一句，素材另起。
- 状态放方括号。方括号的意思是「这是刚发生的事，不是你要说的话」，但括号里不使用「状态」「系统」「回执」。
- 别人的话用 `谁：原话` 或引号，逐字留。概括会改意思。
- 归属写她认识的名字：群名、人、视频标题。不写 `channel=wx`、`surface=bili`。
- 时间用「刚才 / 今天 12:30 / 昨天」。不写 ISO。
- 不确定就写不确定。三种发送结果必须分开，不能为了好听并成「发出去了」：
  - 看见了：`[发到「X」了，末尾能看见]`
  - 只看见预览：`[按下去了，末尾还没看见，先别当发出去了]`
  - 没看见：`[按下去了，没看见落下去。可能出去了，也可能没有]`
- 做不了的原因用她能对哥说的那句，不报错误码。见 §5.4。
- 不报数：不报剩余额度、不报第几次催办、不报帧数、不报输入了几个字、不报置信度。次数若会改变她的做法（第三次之后不再催），用另一句话：「这件事先放着，不用再盯。」

### 5.2 记号怎么写

她下一步真的要用的，才给。给的时候：

- 单独占最后一行，用 `〔〕`，不写「编号」「id=」「task_id」。
- 一条就写 `〔ev_01J…〕`。多条才编号，而且编号只是「第几条」，值跟在后面：`〔1 ev_…〕〔2 ev_…〕`。不要 `1=ev_…`，等号像字段。
- 记号只出现在末行，不在正文里叙述它。**本期不做服务端别名解析**：`task_id`、表情 id、提醒的 id 仍由她从记号行原样带回，工具接受的参数和现在一致。「用名字代替记号」是下期方向。失败文案不要把内部 id 补进去。
- permit 本期仍然在到点提醒里（她要填回 `wx_send`），但不解释它是什么，也不出现在任何别的文本里。机械投递见下期。

### 5.3 工具名留在哪

协议要求 `name` 字段是可调用的标识。这是记号的一种，不是散文。

- `name` 保持 `wx_send` 这种稳定名字。不改名，避免把一次文案整理变成协议迁移。
- `description` 第一句是能力，用世界声：「把一句话发到某个微信会话。」工具名不在这句话里重复。
- 参数说明先说她填什么，参数的英文名只在 schema 的 key 里。不在说明里写 `chat：`、`enter=true`、`what=search`。
- 常驻提示词里不教工具名清单。她看得见的工具，schema 已经在。再写一遍手册，就是每轮给她念接口。
- `her_tools` 的目录必须出现名字，否则她无法 `load`。目录行写成能力，名字放记号：`看屏幕 〔wx_see〕`。不要 `[工具] 1. wx_see — 看屏幕`。

### 5.4 失败原因对照

代码里的 `code` 只进台账。她听见的是右列。没有专用映射时用「没做成，过会儿再试」，不拼 `err.message`，不带路径、堆栈、`ECONNREFUSED`。

| 内部原因 | 她听见 |
| --- | --- |
| 窗口读不到、树落后 | `[没看清。屏幕可能慢半拍]` |
| 会话不在允许名单 / 名单为空 | `[这个会话现在说不了]` |
| 没被 @、窗口过了 | `[这儿现在插不上话]` |
| 主动额度用完 | `[这个群今天先不主动开口]` |
| 频率限制 | `[说得太密了，等一下]` |
| 主机闸：对话框里的问题不要发去微信 | `[这句是在这儿说的，不是发到微信]` |
| 提醒许可不对、过期、文案被改 | `[这句和你当时定的不一样，没发出去]` |
| 缺登录 / cookie | `[说不出去，缺了点什么]` |
| B 站今天说够了 | `[今天说得够多了]`（已有，保持） |
| 看画面额度用完 | `[今天不想再看画面了]`（已有，保持） |
| QQ 里调微信工具 | `[这儿动不了微信]` |
| 预期失败以外的抛错 | `[没做成，过会儿再试]` |

「允许名单里有哪些会话」不进她的上下文。她对一个具体会话试过，才知道这个说不了。把整张名单念给她，她会在群里或对哥报菜单。

最后一行「预期失败以外的抛错」会把真故障都压成同一句话。台账必须继续记原始错误和 `code`，观测台按 `code` 计数，否则运维看不出哪一类在增加。这条是本期验收项（§11）。

### 5.5 和回声的关系

世界声仍然可能被复述。守住三条：

- 不写完整的、像她会说的句子。`[发到「X」了，末尾能看见]` 比 `说出去了：「……」` 难被当成自己的话。
- 不把她刚提交的原文放进成功回执。她知道自己写了什么。失败时如果必须引用，只引对方的话，不引她的。
- `bili_speak` 成功不回显原话。实际发出去的字（例如被加上的 @）若和她写的不同，另说 `[发出去的和你写的不完全一样]`，并把实际文本放在素材块，不放在她的口气里。她要是需要核对，素材块在；不要用「说出去了：「……」」替她说。实施前先确认这个素材块会不会进她下一轮的上下文：会进的话，等于换个位置回显，那就只留 `[发出去的和你写的不完全一样]`，实际文本只进台账。

## 6. 禁词与替换

凡是会进入她上下文的字符串——工具 `description`、参数 `description`、投影、`fish:*` 段、敲门、预期失败的人话——过一张禁词表。测试扫这些字面量。别人的原话、她自己写下的事件正文、视频 OCR 正文不扫：那些是素材，不是我们的声音。

`STYLE_BRIEF` 大方向已经是人话，不动语气样本。要删的是会把她拉去操作台的句子：

- `RECALL_BRIEF` 不再说「小括号里是它的 id」。翻到的结果末行自带记号。

### 7.6 错误

微信发送路径上她会看见的 `throw new Error`，改成 `throw new ToolError(code, 人话)`。**只换文案和加 `code`，判定条件、抛出位置、是否抛出，一律不动。** `tool-result.js` 已有 `ToolError` 和按 `code` 查表的 `projectError`（不拼 `err.message`），本期补充表项即可。覆盖：窗口读不到、会话不对、名单、@ 窗口、额度、频率、主机闸、许可、输入框找不到、文本含换行、树落后。

做法：

- `sendToChat`（`index.js:1122` 起）、`gateSend`、`wx_click`、`wx_type`、`wx_send` 的 `execute` 里，凡是 §5.4 表里有对应项的，换成 `ToolError`。表里没有的保持原样，走兜底 `[没做成，过会儿再试]`。
- 原始 `message`、坐标、名单内容只进台账（`code` 加原始错误），不进 `modelText`。
- `Error: wx_send: text 不能为空。` 这种句子不再出现。参数不合法时：`[这句话发不出去]`。
- 现有 106 处 `throw new Error` 不一次迁完。按「她会读到的」分批，先做发送路径，再做点击、输入、偷看。每批配一条测试：同一组输入，拒绝结果不变，只是 `modelText` 变了。
- 观测台按 `code` 计数（§5.4 末段）。

**为什么不改成信封：** `{ ok:false }` 信封会让宿主把预期失败当成功返回，调用方（含逾期、提醒的代码路径）对 `throw` 的处理会变。那是返回值类型的变化，归下期。

**阶段 A 的失败分支：** 上面的判断只在宿主确认 `ToolError.modelText` 不带 `Error:` 时成立。若实测仍带前缀，本期不能继续按普通 `throw` 交付，也不能把系统声留给用户观察。此时只对受影响的微信工具引入最小错误信封/统一错误渲染通道，并满足四条：

1. 预期失败仍然不会进入成功分支；
2. 台账保留原始错误和 `code`；
3. 成功路径的参数集合、可见性和正常返回形状不被顺带改动；
4. 同一宿主测试必须证明她读到的是世界声，而不是 `Error:` 或内部异常。

若失败分支需要改变受影响工具的成功/失败返回结构，必须在阶段 A 记录为范围变更并重新审查，不能把它伪装成“只改文案”。未受影响的工具仍保持原返回类型，完整信封化继续放在下期。

投影函数自己兜底，失败时给 `[结果没能显示出来]`，不要把 `output.render failed` 送进她的上下文。台账监听器自己吞错，这条返回契约已有，保持。

## 12. 风险

- **过度扮演。** 世界声若写成「你心里一暖」，她会照念。括号里只写事实。
- **过度压缩。** `qq_group_history` 曾经只回条数，闭环断了。读工具必须留下她要读的原话。
- **禁词误伤。** 视频字幕、群消息里本来就有「模型」「API」。扫描器只扫我们的字面量，不扫素材。投影拼接素材时不要把我们的禁词再包一层解释。
- **permit 仍在她的上下文里。** 她可能把它念进群里。本期只能靠口吻降低概率，不能消除。下期解决。
- **删掉手册之后她不会点输入框。** `wx_send` 已经包了点开、输入、回车。手册是给旧的原语路径的。原语留在按需组里，description 写清代价，不在每轮教学。
- **`ToolError` 迁移改变了她读到的拒绝句，但她的重试行为可能变。** 例如以前读到「树落后」会等，现在读到「屏幕可能慢半拍」。用 `gateRejectRate` 和重试次数观察。
- **新旧文案并存。** 同一会话里若微信还是回执、屋子已经是世界声，她会混。验收只看全部接入之后。混合期在台账记 `voiceVersion`，不拿来下结论。
- **成长模板改措辞被当成改人设。** 模板是叫醒时的处境，不是事件。改 prompt 字符串不改 `events.jsonl`。不要顺手改模板的触发条件。
