# 微信后台采集器：持续群上下文与发言人归属

日期：2026-11-04
状态：设计已口头确认，待评审后写实施计划

## 1. 背景

大肥鱼现在只有两种上下文来源：

- 当前打开的会话：每 5 秒读一次消息区，最多 12 条，记进台账；
- 其他会话：只有一个被截断的侧栏预览，而且只有被 @ 时才落进台账。

结果是：没点开过的群没有记录；点开过的群也只有“看到的那一屏”，没有前因后果。
发言人问题更直接：微信 4.x 的无障碍树只给消息正文，不给发言人。
2026-11-04 实测 `Messages` 列表项就是一行 label，没有子节点；台账里 6 个会话、
139 条记录的 `sender` 全是 `null`。侧栏预览里的 `计科4223薛长顺: 那里润`
只能覆盖最后一条，而且现有解析会把 `14:02 开会` 的 `14`、`注意：明天` 的
`注意` 当成人名。

用户要求：

1. 只要大肥鱼挂着，就在看群聊，至少能查到记录；
2. 对人的抓取要更准；
3. 采集是**后台流水线**，不要做成她的工具；她有事或正在说话时，采集器让路；
4. 服务号先不进入大肥鱼。

已确认的取舍：

- 所有非服务会话持续记录侧栏预览（不点开、不动未读）；
- `policy.allowChats` 里的会话额外自动轮转点开读全文（会清未读，用户接受）；
- 每次读当前一屏；首次接触或台账断档时向上回滚最多 3 屏；
- 轮转名单直接复用 `allowChats`（含其中的两个单聊）。

## 2. 目标与非目标

### 目标

- 非服务会话只要有新消息，就在台账留下一条可查记录，即使从未点开。
- `allowChats` 里的会话持续积累全文记录，包括被叫醒之前的那几句。
- 每个可识别的发言人带置信度落盘；识别不了明确写“发言人未识别”，绝不猜。
- 采集器完全后台运行，不注册成她的工具；她在说话、有任务或正在投递时不点开任何会话。
- 服务号/新闻/文件传输不进入台账，也不出现在她的查询结果里。
- 不删除、不覆盖、不重排已有台账和 `events.jsonl`。

### 非目标

- 不改变回复触发规则（@ / 免 @ / 单聊）和发送闸。
- 不读取微信本地数据库，不绕过 UI。
- 不做跨会话的模型摘要或向量重建；沿用现有检索和每日摘要。
- 不改工作台 UI；采集状态只写 `health.json` 和日志，展示留待以后。
- 不追溯补齐历史上没有记录的消息。

## 4. 架构与数据流

采集器是耳朵进程里的一个后台工作者，不是模型可调用的工具。每个 5 秒周期：

```
look() ──> ① 预览流（所有非服务会话，不点开）
      ──> ② 当前会话全文（原有 captureCurrent，补时间/引用/贴纸/OCR）
      ──> ③ 里程计：allowChats 里预览或未读变化 → 入采集队列
      ──> ④ 空闲检查：她忙吗？忙就停在这里，下一轮再看
      ──> ⑤ 从队列取一个到期会话，后台点开 → 读 → 记 → 恢复原会话
```

顺序是刻意的：①②③ 只读，先完成；④ 发现她在说话/有任务就完全不点开；
⑤ 才动 UI。这样“采集”和“她的回复”不会抢同一个会话。

### 4.1 预览流（①）

输入：`look()` 已经拿到的 `parsed.chats`。对每一行：

- 跳过服务号（见 §7）和 `draft=true` 的行；
- 比较 `(preview, time, unread)` 与上一轮快照；没变就不记；
- 变了就追加一条台账：
  - `source: 'preview'`
  - `kind`: `text` / `sticker` / `image` / `file` / `voice` / `video` / `link`
    （由预览开头的 `[Sticker]` 等标记判断）
  - `sender` + `senderConfidence`: 群聊从 `名字: 内容` 解析；单聊用会话名、`high`
  - `text`: 预览正文；表情/图片只留占位符，不冒充正文
  - `at`: 侧栏时间可解析时用侧栏时间，否则用采集时间，`atConfidence` 对应 `low`
- 同一行连续多轮预览不变时不重复写；台账自身的内容去重继续兜底。

预览流不点开、不滚动侧栏、不改变未读。

### 4.2 当前会话全文（②）

保留 `captureCurrent()` 的调用时机，补四件事：

1. **时间行不再当正文**：`14:02` / `Yesterday 16:29` / `Monday` 识别为时间标记，
   给其后的消息补 `at`（跨天用采集日期推断），`atConfidence: 'medium'`。
2. **引用拆分**：`那里润\nQuote 计科4221陈子助's message: 很润是吧`
   → `text: '那里润'`，`quote: { author: '计科4221陈子助', text: '很润是吧' }`；
   引用作者进人物名册，但不改变本条发言人。
3. **贴纸/图片/文件**：`[Sticker]`、`Animated Stickers`、`[Image]` 等标成对应
   `kind`，不进入可检索正文；`Animated Stickers` 若来自表情面板浮层则直接跳过。
4. **OCR 补发言人**：见 §5；对当前会话最多每 20 秒跑一次，
   新记录先以 `sender: null` 入账，随后用 `repair` 补上。

### 4.3 轮转采集（③④⑤）

**入队条件**

- 会话名在 `policy.allowChats` 里；
- 且满足以下任一：预览变化、`unread > 0`、插件启动后还没采集过该会话；
- 启动后的首次采集错开排队，避免一次性连点多个会话；
- 同一会话 60 秒内不重复入队；队列上限 20，超出丢最旧的。

**暂停条件（任一成立就不点开）**

- `hostBusy()`：她在模型回合里；
- `hostState.active`：主机/微信会话正在交谈（不区分是否有微信意图）；
- 当前这一轮还有未投递的 @ 命中，或 `withSendLock` 正忙；
- `policy.enabled === false` 或 `watch === false`；
- 树不是 `ok`、`fresh.stale`、或微信在登录页；
- 最近一次发送/投递结束不到 10 秒。

暂停只影响轮转，不影响预览流和当前会话记录。日志写
`[dsh-wx] 采集：暂停（原因）`，同一原因 30 秒内只写一次。

**单次采集步骤**

1. 记下 `prev = current`；
2. `wx.sh clean` 关浮层；`fresh.reset()`；
3. 若 `current` 已经是目标会话，直接读；否则点侧栏该行，等 700ms，
   重新 `look()` 核对 `current`；不对再试一次，仍不对则退避 120 秒；
4. 记录点击前的未读快照到目录（§6）；
5. 读消息区；首次接触该会话或与台账末条不重叠时，向上滚最多 3 屏，
   每屏按“内容尾部重叠”合并，不重复入账；
6. OCR 发言人（§5），把 `sender/senderConfidence/direction` 和正文一起追加；
7. 扫描新记录的正文：命中 `trigger` 或 `@D33p53Ek` 的，按 @ 命中处理
   （授权 @ 窗口、下一轮投递），避免“先清未读导致 @ 丢失”；
8. 若 `prev` 非空且不是目标会话，点回 `prev`；恢复失败只记日志，不重试。

**限流**

- 全局最多 1 次 / 5 秒；
- 与 `wx_send` 共用 UI 锁，任何时刻只有一个写 UI 的操作；
- 采集失败（点不开/核对不上/树落后）退避 120 秒，不空转。

## 5. 发言人归属与人物名册

### 5.1 OCR 发言人

新增 `wx.sh speakers`（`lib/ocr-speakers.mjs`）：

- 截取微信窗口，裁右侧消息区（宽 66%、高 70%，从 34%/7% 起）；
- 放大 300%，`tesseract -l chi_sim+eng --psm 6 tsv`；
- 输出带屏幕绝对坐标和置信度的文本行 JSON。

纯函数 `alignSpeakers(messages, lines, { scale, origin, roster })`：

- 对每个树消息项，只看它的顶部到下沿 45% 之间的 OCR 行（名字行在气泡上方）；
- 候选必须是“像名字”的文本：1–24 字、无 `:：。，` 等标点、不是时间/系统标记、
  置信度 ≥ 50；
- 候选与名册匹配（先去掉 OCR 插入的空格，再做全名/唯一别名/唯一前缀）；
  匹配上标 `medium`，匹配不上保留原文标 `low`；
- 右侧对齐、且没有名字行的气泡判为 `direction: 'out'`；
- 找不到名字行、也不是出站 → `sender: null`，卡片写“发言人未识别”。

OCR 只补空位：树/预览已经给出结构化 `sender` 的，不覆盖。

### 5.2 人物名册

新增 `~/.dsh-wx/people.json`：

```json
{
  "version": 1,
  "people": [
    {
      "key": "计科4223薛长顺",
      "display": "计科4223薛长顺",
      "aliases": ["薛长顺"],
      "chats": ["c_ef9c60d1344f"],
      "sources": ["preview", "ocr"],
      "firstSeenAt": "2026-11-03T...",
      "lastSeenAt": "2026-11-04T..."
    }
  ]
}
```

- 学习来源：预览前缀、引用作者、OCR 确认过的名字、单聊会话名；
- 归一化：去首尾空白、压连续空白、去掉 OCR 在汉字/数字之间插的空格；
- 别名：`文天聪(w14973)` → 主名 `文天聪`，`(w14973)` 记别名；
- 名册只用于**验证和归一化**，不用来凭空生成发言人；
- 名册坏了按空名册处理，不影响采集。

### 5.3 解析修复

`parsePreviewSender` 增加排除：

- 时间：`^\d{1,2}[:：]\d{2}`、`^Yesterday|Today|Monday|周[一二三四五六日天]`；
- 纯数字/纯标点/系统标记（`[Link]`、`[Sticker]`、`撤回了一条消息` 等）；
- 冒号前少于 1 个或超过 24 个字符；
- 排除后仍读不出 → 不认发言人，保留原文。

## 6. 台账、目录与健康

### 6.1 台账字段（向后兼容，只增不改）

新增可选字段：

| 字段 | 含义 |
| --- | --- |
| `source` | `preview` / `capture` / `tree`（已有，扩展取值） |
| `kind` | `text` / `sticker` / `image` / `file` / `voice` / `video` / `link` |
| `quote` | `{ author, text }`，引用块，不参与发言人归属 |
| `unreadBefore` | 这次采集点开前的未读数（0 表示无） |
| `atConfidence` | `high` / `medium` / `low`，已有字段，时间行解析后填 `medium` |

旧行没有这些字段时按默认值读，不需要迁移。

### 6.2 目录

`directory.json` 每条会话新增：

- `lastNonZeroUnread`：最后一次看到的非零未读数；
- `lastNonZeroAt`：看到它的时间。

点开清掉红点后，这两个字段仍保留，工作台以后可以用它显示“当时有几条”。

### 6.3 健康与日志

`health.json` 增加：

```json
{
  "capture": {
    "paused": true,
    "pauseReason": "host-busy",
    "queued": 2,
    "lastAt": "2026-11-04T...",
    "lastChat": "星晓家园10号楼1302",
    "lastResult": "added:3 skipped:1",
    "lastError": ""
  }
}
```

日志前缀固定 `[dsh-wx] 采集：`，便于 journalctl 过滤。

## 7. 服务号排除

新增 `policy.ignoreChats`，默认包含：

`Tencent News`、`File Transfer`、`Service Messages`、`Weixin Team`、
`微信团队`、`微信ClawBot`、`微信支付`、`服务通知`。

规则：

- 预览流、轮转队列、`wx_history` 列表都跳过这些会话；
- 目录仍可扫描到它们（用于会话枚举和发送闸），但不写台账；
- 已有历史记录不删除，只是不再新增；`wx_history` 查询这些会话时返回“不记录服务号”。

用户以后要放进来，只改 `ignoreChats`。

## 8. 查询接口

新增只读工具 `wx_history`：

```
wx_history({ chat?, query?, hours?, limit? })
```

- 不传 `chat`：列出有记录的非服务会话（名字、最后一条时间、条数）；
- 传 `chat`：按名字在目录里解析，读该会话台账；
  - 有 `query` → 现有词法检索 + 可选向量；
  - 没有 `query` → 最近 `limit` 条（默认 8，最多 20）；
- `hours` 只保留该时间窗内的记录；
- 结果格式与 `wx_context` 的卡片一致：发言人 / 时间 / 来源 / 匹配原因 / 置信度；
- 所有正文过 `guard.js` 的 `sanitizeForeign`；
- 不要求 taskId，也不绑定任务；这是纯读接口，不产生任务、不写事件流。

现有 `wx_context(taskId)` 保持不变，任务内的范围约束不受影响。

## 9. 失败处理

| 情况 | 行为 |
| --- | --- |
| 点开会话后 `current` 不对 | 重试一次；仍不对则放弃，退避 120 秒 |
| 树 `partial` / `down` / `login` | 暂停轮转，预览流也停（没有可信数据） |
| OCR 失败或超时 | 本次采集保留 `sender: null`，不阻塞入账 |
| 台账写盘失败 | 本次放弃，日志记录，下一轮重试 |
| 恢复原会话失败 | 只记日志；下一轮以当前会话为准 |
| 队列积压 | 丢最旧，保留最近 20 个会话 |
| 服务号混入 | 在入队和写台账前双重过滤 |

## 11. 验收

1. 群里连续 3 条、中间一条不是最后一条：预览流至少记到最后一条；轮转后 3 条都在台账，
   发言人正确或明确标“未识别”。
2. 她正在回复时，日志出现 `采集：暂停（host-busy）`，期间不点开任何会话；
   回复结束 10 秒后才恢复。
3. 点开清掉未读后，`directory.json` 的 `lastNonZeroUnread` 仍保留原值。
4. 服务号不出现在预览台账、轮转队列和 `wx_history` 列表里；旧记录仍在。
5. `wx_history` 能按群名查到最近记录；正文经过 `guard.js`。
6. 采集期间 `wx_send` 不被抢占；采集与发送不交叉。
7. 现有测试全绿；新增测试覆盖 §10。


## 13. 风险与开放点

- **未读被清**：用户已接受。目录保留快照，但手机端的已读状态无法恢复。
- **OCR 开销**：只在采集和当前会话变更时跑，单会话冷却 60 秒；OCR 失败不阻塞。
- **UI 竞争**：采集与发送共用锁；她在说话时完全暂停。工作台人工操作仍可能与采集
  交叉，但每个操作都会重新核对 `current`。
- **贴纸/表情面板**：采集前 `clean`；面板项不是消息，跳过。
- **坐标/缩放漂移**：OCR 与树坐标都按 `screenScale()` 换算；用 fixture 锁住换算，
  真机异常时退化为“发言人未识别”，不阻塞记录。
- **隐私**：非服务会话的预览都会落盘，和当前打开会话的记录同等级，沿用现有文件权限。
- **服务号边界**：名单是显式的；新出现的服务号如果没进名单，会先被当普通会话记录，
  需要时补进 `ignoreChats`。
