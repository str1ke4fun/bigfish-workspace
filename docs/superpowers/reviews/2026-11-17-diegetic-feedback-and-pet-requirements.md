# 大肥鱼反馈与桌宠需求清单（审阅稿）

日期：2026-11-17
状态：待用户审阅；不是实施计划。

本文把三份新设计整理成可逐条审阅的需求，并把已确认的取舍、前置验证和后续路线图放在一起。

来源：

- [反馈不拆台（措辞层）](../specs/2026-11-16-diegetic-feedback-design.md)
- [机械侧接管（下期路线图）](../specs/2026-11-16-diegetic-feedback-phase2-design.md)
- [桌宠新动作与事件链设计](../specs/2026-11-16-pet-event-chain-design.md)

## 1. 结论

- **反馈措辞层**：目标是把大肥鱼读到的文本从“系统对模型”改成“世界对她”，不改权限、闸和可见性。
- **机械侧接管**：是待验证路线图，不是整体实施包；按项目逐项验证、设计和上线。
- **桌宠一期**：可以进入实现计划，前提是先完成组件映射实验。
- **桌宠二期**：先做事件源验证，不在一期顺带接事件。

## 2. 已确认决策

| 编号 | 决策 | 结果 |
| --- | --- | --- |
| D-01 | 提醒到点文案 | 世界声句子 + 会话名和原文逐字保留 + 末行一次性凭据；不出现 `chat:` / `text:` 操作块 |
| D-02 | `ToolError` 宿主验证失败 | 不接受 `Error:` 进入她的上下文；本期改用只覆盖受影响微信工具的最小错误通道，并视为范围变更 |
| D-03 | 桌宠循环动作 | `loop:true` 是持续手动状态，由新动作、“停下当前动作”、拖动或皮肤切换结束 |
| D-04 | 桌宠菜单维护 | 一期手动重新载入；常用保留原 7 项；其余 7 个槽动作放“状态”分组；未登记素材不自动发现 |
| D-05 | 休息来源 | 日程窗口 A 为主，手动 C 覆盖，不做空闲超时 B |
| D-06 | 休息时点击 | 显示固定短句“在休息”，不调用模型 |
| D-07 | 桌宠说话气泡 | 使用已发生原话的截断版本，短 TTL；桌宠不生成新文案 |
| D-08 | `task_id` 收敛 | 先只移除 `wx_send` 的必需句柄；`wx_context` / `wx_task_*` 在没有可靠当前会话前继续使用记号 |
| D-09 | 余额 | 不做 |
| D-10 | 桌宠 presence | 保留现有 `presence.on → thinking`；休息 scene 优先于 presence |

## 3. 路线图

| 阶段 | 内容 | 进入条件 | 产出 |
| --- | --- | --- | --- |
| P0 验证 | 宿主错误呈现、桌宠映射实验、提醒回调、会话名称映射、当前会话语境、二期事件源 | 三份设计已复审通过 | 每个 Gate 一份可复核结论，失败则改设计或降级 |
| P1 可并行 | 反馈措辞层；桌宠一期播放层 | P0 对应 Gate 通过 | 两套可独立上线、可独立回滚的行为 |
| P2 低风险机制 | 逾期催办调度；`wx_send` 隐式任务绑定 | 措辞层已验收；任务唯一性和名称映射已验证 | 不再每分钟制造催办；旧显式参数仍兼容 |
| P3 中风险机制 | 提醒到点机械投递；配额分层；桌宠二期事件链 | 提醒重启恢复/失败语义明确；发言分布样本足够；事件源可用 | 机械侧接管凭据、计数和事件动作，权限闸不放宽 |
| P4 数据形状 | 微信返回信封化；参数面收口；图片块；测试副本清理 | 每项有独立迁移、回滚和调用方清单 | 数据契约升级完成，旧路径和失败降级明确 |

## 4. 前置验证 Gate

| Gate | 必须回答的问题 | 不通过时 |
| --- | --- | --- |
| G-01 | `ToolError.modelText` 经宿主后是否不带 `Error:` 前缀 | 启用 D-02 的最小错误通道，更新范围后重审 |
| G-02 | 运行中替换桌宠 config 是否会打断/残留当前动画 | 改用预写动画池或独立视频层，不进入一期实现 |
| G-03 | `dsh-pet-component` 的完成/切换回调能否可靠驱动 `seq` 和恢复 | 补实验或调整组件接入，不用固定延时冒充完成 |
| G-04 | 宿主定时任务是否能给插件结构化到点回调 | 自建持久化计时器并定义重启恢复，或暂缓机械提醒 |
| G-05 | `wx_send` 能否把目标会话名稳定映射到 `chatId` | 隐式绑定不能作为默认路径，保留 `task_id` |
| G-06 | `wx_context` / `wx_task_*` 的 `exec` 是否有可靠当前会话 | 这些工具继续要求 `task_id`，不猜任务 |
| G-07 | `utterance`、`bili_reply`、rest、outing 是否有可订阅事实源 | 对应桌宠 trigger 不排期，暂停二期该部分 |

## 5. 反馈措辞层需求

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| D-11 | 她读到的文本统一为世界声；协议名和必需记号可以保留 | 常驻文本无禁词；工具名只在协议字段和目录记号出现 |
| D-12 | 微信每轮的通道规则和工具手册合成一段短规则 | 不再挂“微信工具手册”；保留 @、主机问话、群内只说事等判断依据 |
| D-13 | 常驻工具说明压成能力 + 一条易错边界 | 参数集合、schema、可见性不变；`her_tools` 目录可读 |
| D-14 | 工具返回改成“发生了什么”，不写回执、额度、任务板、内部字段 | 成功、仅预览、未确认三句分开；失败不假装成功 |
| D-15 | 耳朵与逾期改成世界声，保留会话、谁、原话预览 | 不出现名单、台账、任务板 id 解释、未读计数和操作口吻 |
| D-16 | 提醒到点使用固定模板，准确携带会话、原文、凭据 | 端到端模拟回填 `wx_send`，三个参数逐字相等；permit 残余风险写入验收 |
| D-17 | `bili_speak` 成功不回显她刚写的原话 | 成功回执不包含原话；实际文本差异只走允许的素材/台账路径 |
| D-18 | 预期失败走 `ToolError`，原始错误和 `code` 只进台账 | 同一输入闸结果不变；宿主 Gate G-01 通过；失败句可读 |
| D-19 | 删除工具教程式身份提示，不写“你是 AI”“请像人一样” | 不新增人格设置、角色扮演指令或回复后润色 |
| D-20 | 配额余额和 @ 窗口分钟数退出她的常驻规则段 | 规则段不含余额；工作台配置仍可调；闸逻辑不变 |
| D-21 | 增加禁词扫描、回声、第四面墙、假成功和闸拒绝指标 | 扫描范围限定我们的静态字面量；素材变量和用户原话不误伤 |
| D-22 | 旧工具返回契约加部分取代说明 | 台账、三态、投影分离仍按旧契约；措辞和预期错误呈现按新设计 |

## 6. 机械侧后续需求

| ID | 需求 | 验收/前置 |
| --- | --- | --- |
| M-01 | 到点提醒由机械侧投递，permit 不进入她的上下文 | G-04；失败重试、重复发送、重启恢复和失败告知都有结论 |
| M-02 | `wx_send` 按目标会话自动绑定唯一活动任务，显式 `task_id` 继续兼容 | G-05；带错 `task_id` 仍拒绝；自动绑定只在实际成功后记一次 |
| M-03 | `wx_context` / `wx_task_*` 在可靠当前会话语境出现前继续使用 `task_id` | G-06；不得跨会话猜任务 |
| M-04 | 微信工具返回信封化，统一完整结果、台账和模型投影 | 106 处 throw 的调用方有清单；`ok:false` 与 throw 的语义分开 |
| M-05 | 参数面收口按数据证据逐项决定，不一次性删除 | `wx_click` 坐标、`growth_commit.confidence`、表情 id、`qq_napcat_api` 各自有迁移和回滚 |
| M-06 | 配额从“事前余额”改为软上限 + 高熔断 + 事后世界声 | 权限类闸不放宽；@ 窗口和 `speechGate` 仍为硬闸；有真实分布后再定阈值 |

| M-08 | 逾期催办第三轮后降频/合并/静默，三选一 | blocked 任务仍进入 `her_inbox`；工作台提示人工处理 |
| M-09 | 清理拆包前 `look/watch/speak` 副本 | 先迁移测试引用；不改变运行时注册面 |

## 7. 桌宠一期需求

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| P1-01 | 动作注册表是开放数据，id → 动画/序列 + 播放方式 | 重复 id 覆盖；缺 webm 丢弃该条；路径穿越被拒 |
| P1-02 | 通过 14 个播放槽播放任意注册动作 | 114 段可手动演出；新增登记后不改代码可演示 |
| P1-03 | 实现借用槽播放状态机 | 一次性、顺序、循环、抢占、停止、恢复均有测试 |
| P1-04 | 循环动作作为持续手动状态 | 不依赖播放完成；新动作/停止/拖动/皮肤切换可终止 |
| P1-05 | 菜单按组展示；常用保留原 7 项 | 其余 7 个槽动作仍可从“状态”组访问；无未登记分组 |
| P1-06 | 手动重新载入动作；不监听文件变化 | 重载后立即 `hello`，新 action id 可被 `/pet/act` 使用 |
| P1-07 | `/pet/act` 接受 `action`，旧 `motion` 兼容 | 未知/未上报 action 返回 400；14 槽旧载荷不受影响 |
| P1-08 | 一期只扩动作协议和内存状态，不接事件源 | `/pet/state` 的 activity 不变；不写 `events.jsonl` |
| P1-09 | 真机验证透明、闪烁、稳态恢复和权限边界 | 单测、菜单可点、真机逐类抽查分别记录，不能互相冒充 |

## 8. 桌宠二期需求

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| P2-01 | 动作清单与触发表是两张独立表 | 无 trigger 的动作仍能手动演出；缺 trigger 不报错 |
| P2-02 | trigger 文件支持权重、`once`、`minGapSec`、`inAmbient` 和皮肤覆盖 | 文件顺序确定；权重校验；皮肤同 `when` 覆盖默认 |
| P2-03 | `/pet/state` 增量增加 `scene` 和 `cues`，旧字段不动 | cue 有 id、kind、text、at、ttl；最多 8 条；离线过期不补播 |
| P2-04 | 稳态优先级包含 presence | `waiting > scene > 其他 activity > presence:thinking > idle`，ambient 只在无稳态时 |
| P2-05 | 休息默认来自日程，手动可覆盖 | A+C；不做 B；点击显示“在休息”；手动起来可覆盖当前窗口 |
| P2-06 | 发言/被回复 cue 可触发动作和截断原话气泡 | 内容只来自已发生事实；桌宠不拼文案；TTL 后可丢弃 |
| P2-07 | 服务端只报事实，不报素材名或动作选择 | 换皮肤不需要改 `dsh-fish`；trigger 在桌宠侧解析 |
| P2-08 | 事件源未验证不得进入实现 | utterance、bili_reply、rest、outing 各自有可订阅事实源和纯函数测试 |
| P2-09 | 余额不做 | 新配置和菜单不出现余额相关入口 |

## 9. 不做与不可越界

- 不新增人格设置、好感度数字、情绪标签或用户直接写人设的入口。
- 不删除、覆盖、重排 `events.jsonl`；桌宠和投影不写事件流。
- 不为“更像人”放宽权限、发送闸、permit、guard、@ 窗口或频率熔断。
- 不把未发出的消息说成已发出；不把单测通过说成模型/消息链路验收。
- 不把素材、个人排查记录、日志、凭据和本地运行数据提交进仓库。

## 10. 仍需后续确认的产品问题

这些问题不影响当前 P1 设计，但进入对应项目前需要拍板：

1. 桌宠休息期间，`speak` / `bili_replied` cue 是否播放动作。当前建议播放配置动作，但不改变 rest scene。
2. blocked 任务第三次后是静默、合并到下一轮，还是只降频；当前只确定仍要出现在 `her_inbox` 和工作台。
3. 桌宠 ambient 的安静时段和 `minGapSec` 默认值，需要真实使用样本后调参。
4. `growth_commit.confidence` 删除后的历史数据迁移与新值默认，尚未到可决策阶段。
