## 1. 背景与问题

当前 8788 工作台已经能覆盖管理功能，但结构是八项平铺：

> 总览 / B 站 / 记忆 / 环境 / 通道 / 工具与规则 / 数据与运维 / 原理

问题集中在三处：

1. **没有“人”的入口。** 打开后先看到的是状态卡和时间线，但 B 站、通道、记忆、环境各自平级，缺少“她今天怎么样 → 哪个世界需要我 → 点进去处理”的路径。
2. **日常与配置混在一起。** B 站页把视频足迹、待回复、登录、风控、界面偏好、证据放在同一列；通道页把进程控制、会话内容、说话策略、人工代操作混在同一页。高频动作要在一堆低频表单里找。
3. **视觉是通用运维后台。** 深灰蓝、卡片网格、字号偏小；信息够用，但没有属于大肥鱼的识别度。

代码层面还有两个扩展瓶颈：

- `workbench/assets/channels.js` 是 599 行单体，QQ、微信、说话频率、掉线提醒、画面、动作日志全部混在一起。
- `workbench/index.html` 把整个通道页的 DOM 硬编码在 HTML 里，加一个通道要同时改 HTML、外壳、总览、轮询和测试。

用户的实际使用频率是：**看她今天怎么样、管 B 站、管通道**；调参排障通常交给第三方 CC，但工作台需要保留直观的日志和必要配置。

## 2. 目标与非目标

### 2.1 目标

1. 打开工作台 30 秒内能判断：她是否正常、B 站是否需要介入、通道是否掉线。
2. B 站和通道各自有一条完整的“今天 → 处理 → 回今天”的旅程。
3. 原通道交互窗口的功能一个不少：QQ 消息与人工发送、说话范围、掉线提醒；微信实时画面、点按、打字、回车、允许说话、补扫、清理。
4. 建立一套可复用的视觉语言：日间暖纸、夜间墨色，衬线用于她的话，无衬线用于数据。
5. 建立通道适配器与页面注册表：以后加通道或加世界页，不改外壳。
6. 保持零依赖、本机单用户、只绑 `127.0.0.1`、BFF 与插件安全边界不变。

### 2.2 非目标

- 不把聊天搬进工作台。连续聊天仍在 8710；工作台只保留“打开她的界面”和一次性“跟她说一句”。
- 不新增账号体系，不把 8788 暴露到本机之外。
- 不新增 B 站代发评论、代回复、批量操作。
- 不新增插件 HTTP 路由，不改事件 schema，不改记忆召回。
- 不做事件全文检索。
- 不在这一版实现新通道（语音、QQ 小号、其他平台）；只定契约和落位。
- 不做 Windows 桌面交付。
- 不删除旧页面文件，直到新页面验收通过并保留一个版本的回滚窗口。

## 3. 设计原则

1. **人优先。** 首页先回答“她今天怎么样”，再回答“哪个世界需要我”。
2. **三色状态。** 绿 = 正常，琥珀 = 注意，珊瑚 = 需要你。除状态点和人工标记外不滥用颜色。
3. **动作就近。** 解冻放在风控卡，扫码放在 QQ 卡，读正文放在待回复行；不要求先跳设置页。
4. **一配置一归属。** 同一个配置键的详细表单只在一个页面；其他页面只给跳转链接。唯一的快捷例外是「刷站 / 评论」两个布尔开关：B 站 · 今天只翻转这两个值，完整表单仍在 B 站 · 管理。
5. **人工可见。** 以她身份发送、打字、按键，一律带“人工”标记、发送前二次确认、写入动作日志，不写事件流，不算她说的。点画面只算界面操作，也记日志，但不改她的话。
6. **低频不抢位。** 配置、日志、备份、原理沉到二级页；一级导航只保留四个入口。
7. **零依赖。** 只用原生 HTML/CSS/JS，不引入框架、图标库、字体文件或构建步骤。
8. **安全边界不动。** Host/Origin/CSP、BFF 白名单、上游 `confirm` 字面量、`textContent` 渲染规则全部保留。

## 4. 信息架构

### 4.1 一级导航

左侧书脊固定四项：

| 一级页 | 一句话 | 默认二级页 |
| --- | --- | --- |
| 她 | 她今天怎么样、记得什么、长到哪了 | 今天 |
| B 站 | 她在外面看了什么、说了什么、要不要介入 | 今天 |
| 通道 | QQ / 微信在不在、能不能说话、必要时人工代操作 | 总览 |
| 系统 | 设置、工具、日志、数据、原理 | 设置 |

一级页顺序即重要度。侧栏每项带一个状态点：

- 她：她是否醒着 / 服务是否正常。
- B 站：风控是否冷却、是否有待回复。
- 通道：QQ / 微信是否掉线或健康异常。
- 系统：不显示状态点。

系统页不显示状态点，避免把低频入口做成告警源。

## 5. 用户旅程

### 5.1 日常巡检（约 30 秒）

1. 打开 8788，落在 `#her/today`。
2. 首屏依次看到：待裁决条（如果有）→ 她的状态与今日四个数字 → B 站摘要 → 通道摘要。
3. 三处状态点都是绿：看完“她留下的话”或最近动作就结束，不点进二级页。
4. B 站摘要出现琥珀 / 珊瑚：点摘要卡进入 `#bili/today`，看风控与待回复。
5. 通道摘要出现琥珀 / 珊瑚：点摘要卡进入 `#channels/overview`，看 QQ / 微信。
6. 处理完点侧栏「她」回到今天；动作日志留下一条“你做了什么”。

### 5.2 B 站异常介入

入口：`#her/today` 的 B 站摘要，或侧栏「B 站」。

1. `#bili/today` 顶部四个数字：今天刷站、今天出门、待回复、风控。
2. 风控冷却：风控卡显示冷却到几点、撞过几次；点“解冻”二次确认，成功后回读状态。
3. 有待回复：待回复行显示视频标题、评论者、正文；“读正文”按需调 `/comment-body`，失败时行内显示原因，不白屏。
4. 需要她再去看一轮：点“人工让她去看 B 站”，调 `POST /wake?focus=browse`；被配额或时段拒绝时，显示上游原因。
5. 只想调开关：刷站 / 评论开关在页面顶部，点一下写 `POST /config`，保存中禁用，失败回读并提示。
6. 想看更多：点“在足迹里按天看”进入 `#bili/footprint`。
7. 想改配额、时段、避让词：进入 `#bili/manage`；日常页不放大表单。

### 5.3 通道掉线处理

入口：`#her/today` 的通道摘要，或侧栏「通道」。

1. `#channels/overview` 四张卡：QQ、微信、说话节奏、她（8710）。
2. QQ 红点：点“去 QQ”进入 `#channels/qq`。未登录时二维码自动换码；点“启动 / 重启”后等状态回读。掉线提醒的开关、轮询秒数、催办分钟、恢复提醒在这一页保存。
3. 微信琥珀点：点“去微信”进入 `#channels/wx`。先看实时画面与无障碍树状态；树不完整时显示元素数、会话数与“侧栏读不到”的原因；点“识别界面”复检，必要时“补扫会话目录”。
4. 人工代操作：QQ 在消息页输入后点“人工发送”；微信在实时画面下点“人工打字 / 人工回车 / Esc”。两者都二次确认，动作日志带“人工”标记。
5. 处理完回 `#channels/overview`，确认状态点变绿。

### 5.4 睡前翻看

入口：侧栏「她」→「记忆」。

1. 切到夜间模式（侧栏底部“日 / 夜”）。
2. 记忆页分段：事件 / 日记 / 日报 / 判断 / 模板。
3. 日记和日报用衬线字、宽行距，像读一页手账；事件列表保持无衬线、时间等宽。
4. 不提供全文检索；事件只按类型和条数筛选，页面上明确写清楚。
5. 信箱未读在「她 · 今天」有入口；读完可以标为已读。

### 5.5 排障（交给第三方 CC）

入口：侧栏「系统」→「日志」。

1. 日志页四个分段：她的时间线、人工动作、工具台账、运行日志。
2. 她的时间线按类型 / 条数筛选；工具台账按日期 / 工具名筛选；运行日志按行数读取。
3. 需要把材料交给 CC：用“导出日志”下载纯文本，或用“复制数据路径”把路径放进剪贴板。
4. 需要看配置：系统 · 设置只保留成长 / 通知 / 对话 / 记忆；B 站和通道页各给“去对应页面”的链接，不复制表单。
5. 需要看服务：通道 · 总览的“她（8710）”卡片显示是否在跑、事件数、最后写入时间、HTTP 状态。

## 6. 页面设计

### 6.1 外壳

```

│              │                                              │

│ 打开她的界面  │                                              │
│ v0.1.0       │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

- 侧栏宽 216px，固定；品牌用衬线字，副标题“她的工作台”。
- 四个一级项：图标位置用状态点，文字左对齐；当前项用暖色底和深色文字。
- 侧栏底部：日 / 夜切换、打开她的界面、版本号。
- 窄屏（< 900px）：侧栏收成顶部条，品牌 + 四个一级项横向排列；二级页签横向滚动；内容区单列。
- 页面标题用 24px 衬线；二级页签用下划线；页面动作（刷新、保存）放在标题右侧。
- 内容区最大宽度 1180px，左右留白 28px；卡片间距 16px。

### 6.2 她 · 今天

```
[待裁决条：她提了一张申请 …… 批准 / 驳回]
┌────────────────────────────────────────────────────────────┐

┌──────────────────────────────┬─────────────────────────────┐
│ 今天的时间线                  │ B 站                         │

- 数据：`status`、`state`、`bili/status`、`tools`、`events?limit=40`、`beliefs`、`inbox`、`home`、`away`、`/api/status.log`、`rules`。
- 进入页面取一次；重读 60 秒一次，但 `GET /inbox` 只在进入页面时读（它本身会重写信箱文件），自动刷新不碰。
- 待裁决条来自 `rules.pending`；批准 / 驳回后重新读 `rules` 和 `beliefs`。
- “跟她说一句”是内联输入框，可带一张图；成功后展示她这一轮说的话；不提供历史会话。
- “叫醒她”调用 `POST /wake`；409 时显示上游 `error` / `why`。
- 空态：没有事件时写“还没有事件”；没有判断时写“还没有长出来的判断”；没有信箱时写“还没有。这是起点，不是故障。”
- 错误态：状态卡失败时显示“读不到：<原因>”并给重试；其他卡片独立失败，不整页白屏。

### 6.3 她 · 记忆

- 顶部一个分段控件：事件 / 日记 / 日报 / 判断 / 模板。
- 事件：类型下拉（全部 / meta / utterance / revise / refusal / reunion / narration / saw）、条数（50 / 100 / 200 / 500）、读取按钮；列表每行是时间、类型 chip、正文。明确写“只做类型和数量筛选，不提供全文检索”。
- 日记：按天选择；不可见时只给日期目录和“日记已写，但设置为不可见”；正文用衬线、宽行距。
- 日报：按日期选择，`pre` 里保留原始 Markdown 文本；不提供导出（工作台只做只读预览）。
- 判断：四段——还在拿着的、被推翻的、拒绝记录、自我修改尝试；原样列出，不做裁决。
- 模板：表格列出 id、阶段、问什么、一次性、来过、次数、最近。
- 全部只读；记忆预算等配置在系统 · 设置。

### 6.4 她 · 成长

- 阶段卡：第几天 / 成长天数、当前阶段、下一个瓶颈（`pendingGate`）、阶段是否被强制推进（`stageForced`）。
- 数字卡：判断条数、张力数、固化条数、疤的数量、立场数、立场是否就绪（`stanceReady`）。
- 判断卡：最近 8 条仍在拿着的判断，点击进入记忆页的判断全文。
- 张力卡：只显示“有几处对不上”和第一对原话，不给裁决按钮；哪句对她，得她自己定。
- 疤与拒绝卡：只显示数量与拒绝记录摘要，不评价对错。
- 规则卡：规则分层与待裁决状态，链接到系统 · 工具与规则。
- 明确写“这里没有数值滑杆，不提供调人格的入口”。
- 数据：`/state`、`/beliefs`、`/rules`；全部只读。

### 6.5 B 站 · 今天

```

│                              │ [人工让她去看 B 站]          │
│ 今天看了什么                  │ 开关与登录                   │

- 顶部“刷新评论”会真的去 B 站扫回复，只在进入页面或点按钮时调用；不做自动轮询。
- 写操作后的回读不触发评论扫描；页面显示“更新于 HH:MM:SS”。
- 刷站 / 评论开关直接写 `POST /config`；保存中禁用，失败回读当前值并提示。
- 未存 cookie 时，登录卡显示暖色提示和“去管理存登录”，可通过 `ui.ownerHintDismissed` 关闭提示。
- 风控冷却时，解冻按钮才出现；解冻二次确认，成功后回读。
- 视频行内的“抽帧”按需加载 `/sheet/<bvid>`；失败时行内说明“这集没有可用的抽帧”。
- 待回复不提供“替她回复”；只提供读正文和人工叫醒。
- 空态：没有待回复写“现在没人回她”；没看过视频写“她还没看过什么”；风控正常写“没在冷却”。

### 6.6 B 站 · 足迹

- 分段：视频足迹 / 评论足迹。
- 视频足迹：按天分组的折叠列表，默认展开最近一天；每条含封面（懒加载）、标题（新窗口打开 B 站）、UP、时间、时长、播放量、抽帧按钮；天数可选 7 / 14 / 30。
- 评论足迹：她发过的评论与回复，按时间倒序；正文缺失时给“读正文”；每条标注 BV 号和视频链接。
- 只读；不提供编辑、删除、代发。
- 空态分别写“还没看过什么”“她还没在 B 站发过评论”。

### 6.7 B 站 · 管理

分组折叠卡，每组独立保存、保存后重新读 `/config` 回读：

1. **登录**：领养人 mid、昵称、cookie（密码框，留空 = 不改）；显示 cookie 是否已存、是否带 csrf、登录账号名；“测试这份 cookie”联网验证；保存只发填了的字段，避免把已存值清空。
2. **风控**：冷却状态、撞过次数、最近 code；解冻二次确认。
3. **浏览**：刷站开关、每天次数、每次看几条、轮换分区数、深读评论条数、弹幕条数、额外搜索词、刷站时段、读评论区。
4. **看画面**：看画面开关、每天几条、每条抽几帧、认画面里的字。
5. **评论**：评论开关、每天评论几条、每天回复几条、允许回回复、扫描间隔、评论时段、@ 领养人。
6. **避让**：避让词、避让 UP mid、最短时长。

- 每个键都有中文标签；数组类输入用逗号分隔，空数组合法。
- `lastShown` / `lastScanAt` 这类运行期内部状态不显示、不回写。
- 页面顶部写明“这些配置只影响她在 B 站的行为；成长与记忆设置在系统 · 设置”。

### 6.9 通道 · QQ

分段：消息 / 说话范围 / 掉线提醒 / 登录与 WebUI。

**消息**

- 左侧会话列表（群 / 私聊、名称、最后时间），点选后加载历史。
- 消息区：发言人、时间、气泡；自己的消息右对齐。
- 底部输入框 + “人工发送”；发送前 `confirm` 二次确认，文案写明“人工代操作：以她的身份把这句话发到……”。
- 发送成功后刷新当前会话；失败显示原因；动作日志由服务端记，不写事件流。

**说话范围**

- 私聊、群、管理员三组 chip，勾选即白名单；列表来自 NapCat，包含已存但不在好友列表的号。
- “群里要 @ 她才回”开关。
- 保存后可选“重启她（约 10 秒）”；勾选时保存前二次确认。
- 摘要行显示：私聊 N 人 · 群 N 个 · 管理员 N 人 · 群里要 @ / 不用 @。

**掉线提醒**

- 掉了就提醒、每 N 秒看一次日志、N 分钟催一次（0 = 只提醒一次）、QQ 回来了也说一声。
- 保存、试弹一条；显示当前登录阶段（在线 / 被踢 / 未登录）。

**登录与 WebUI**

- 启动 / 停止 / 重启；二维码（未登录时自动换码）；NapCat 面板、登录页、WebUI token 复制。

### 6.10 通道 · 微信

分段：实时画面 / 允许说话 / 维护。

**实时画面**

- 大画面约 1 秒一帧；只在页面可见且微信在跑时拉帧；失败显示“截不到图（Xvfb 或微信没起）”。
- 点画面 = 在那个坐标点一下微信窗口；坐标按图片原始尺寸换算。
- 人工打字 / 人工回车 / Esc：发送前二次确认，文案写明“人工代操作”；结果显示在画面下方或状态行。
- 画面下方显示 Xvfb、窗口尺寸与位置、多余界面数量、无障碍树状态。

**允许说话**

- “允许她在微信里说话”总开关；关掉 = 微信工具全部拒绝。
- “也要 @ 她才回” + 被 @ 之后还能说 N 分钟。
- “能开口的会话（群聊）”名单；“这些会话不用 @”名单（私聊、文件传输）。
- 名单为空 = 她开不了口；页面上明确写。
- 候选来自微信检测；检测失败时禁用保存，避免把页面默认值写回去；名字坏成问号时提示重新勾选。
- 保存后立刻生效，下一轮她就能读到。

**维护**

- 补扫会话目录（只滚侧栏、不点开会话、不碰草稿）。
- 关掉多余界面、存一张、识别界面、清理帧存档。
- 这些是维护动作，不写事件流；清理前二次确认。

### 6.11 系统 · 设置

- 顶部“配置搬家”说明卡（见 4.4）。
- 四组折叠卡：成长、通知、对话、记忆；每组独立保存，保存后回读 `/config`。
- 每个键都有中文标签；`persona` 永不出现。
- 低风险，但仍然是低频页；不放在一级导航。

### 6.12 系统 · 工具与规则

- 工具清单：`/tools` 只给名字；点一个 chip 加入白名单。
- 工具白名单：收窄工具面开关、每行一个工具名的文本域、保存；保存后提示“重启 DSH 后生效”。
- 规则分层：申请开关状态（只读）、待裁决卡（链接到「她 · 今天」）、规则在哪一层、近来的裁决；本页不新建、不编辑规则。
- 自检：点按钮才跑，联网；结果按 ✓ / ✗ 列出，失败的给“怎么修”；原始返回折叠。

### 6.13 系统 · 日志

四个分段，统一行样式：

1. **她的时间线**：`/events?type=&limit=`，类型 chip + 时间 + 正文；只读。
2. **人工动作**：`/api/status.log`，最近 20 条；人工动作带“人工”chip；只读。
3. **工具台账**：`/ledger?date=&tool=`，按日期 / 工具名筛选；每条可展开原始返回；只读。
4. **运行日志**：`/log?lines=` 预览最近 N 行；“导出日志”走 `/log/export`；“清空运行日志”二次确认。

- 运行日志和原始返回用等宽字体、可换行、可滚动。
- 页面顶部写明“她的时间线是记忆，不是运行日志；运行日志只用于排障”。

### 6.14 系统 · 数据

- 备份与恢复：下载备份（流式，约 47MB）；恢复要选 JSON、输入 `restore`；恢复后提示重启 DSH。
- 导入：只在她还没有起点时可用；读取 / 下载交接单模板；导入前二次确认；人设 1200–1500 字，超过 2000 字上游拒收。
- 重置：输入 `reset`；说明“封存旧档，不删除”。
- 更新检查：只在点按钮时查一次。

## 8. 交互窗口与扩展性

### 8.1 通道适配器契约

每个通道是一个模块，导出同一种形状：

```js
// assets/channels/<id>.js
export const channel = {
  id: 'qq',                 // 唯一 id，用于 hash、日志、状态映射
  label: 'QQ',
  order: 10,                // 总览里的排序
  badge(status),            // → 'ok' | 'warn' | 'bad' | null
  summary(status),          // → { lines: string[], actions: Node[] } 或直接返回 DOM
  renderPanel(root, ctx),   // 建页签 DOM 骨架
  refresh(ctx),             // 拉首屏数据 / 后续刷新
  leave(),                  // 切走时停轮询 / 停帧循环
  humanActions: ['send'],   // 需要“人工”标记和二次确认的动作
}
```

`assets/channels/registry.js` 只做注册：

```js
import { qq } from './qq.js'
import { wx } from './wx.js'

export const CHANNELS = [qq, wx].sort((a, b) => a.order - b.order)
```

外壳、总览、页签、轮询只遍历 `CHANNELS`，不出现 `if (id === 'qq')` 这类分支。

### 8.2 页面注册表

每个二级页是一个模块：

```js
// assets/pages/<id>.js
export const page = {
  id: 'her-today',
  nav: 'her',               // 所属一级页
  label: '今天',
  order: 10,
  badge(ctx),               // 可选
  enter(root, ctx),         // 首次渲染 + 启动轮询
  leave(),                  // 停轮询
}
```

一级页注册表：

```js
// 把通道契约适配成页签契约；外壳只认页面描述，不认通道内部形状。
const channelPages = CHANNELS.map((ch) => ({
  id: ch.id,
  nav: 'channels',
  label: ch.label,
  badge: (ctx) => ch.badge?.(ctx.status?.channels?.[ch.id]),
  enter: async (root, ctx) => { await ch.renderPanel(root, ctx); await ch.refresh?.(ctx) },
  leave: () => ch.leave?.(),
}))

export const NAV = [
  { id: 'her', label: '她', pages: [herToday, herMemory, herGrowth] },
  { id: 'bili', label: 'B 站', pages: [biliToday, biliFootprint, biliManage] },
  { id: 'channels', label: '通道', pages: [channelsOverview, ...channelPages] },
  { id: 'system', label: '系统', pages: [sysSettings, sysTools, sysLogs, sysData, sysPrinciples] },
]
```

- `channelPages` 是唯一的适配层：通道模块保留 `renderPanel` / `refresh` / `leave`，外壳只消费统一的 `enter` / `leave`。
- `renderPanel` 只建 DOM 骨架；`refresh` 负责首屏和后续数据。`enter` 先 `renderPanel` 再 `refresh`，后续刷新只调 `refresh`，不重复建骨架。
- 加一个新通道 = 写通道模块 + 在 `CHANNELS` 注册；页签、路由、总览、状态点自动出现。
- 加一个新世界或新系统页 = 新页面模块 + 在一级页注册表加一行；不改外壳的 DOM 结构。

### 8.3 动作日志统一模型

服务端 `note()` 已经写入 `{ at, who, text, ok }`，人工动作通过 `extra` 带 `operator: 'human'`。新通道沿用同一形状，并补两个可选字段：

```js
{
  at: '15:04:02',
  who: 'qq',            // 通道 id / 'her' / 'system'
  text: '人工发送到群「内部赤石群」',
  ok: true,
  operator: 'human',    // 人工代操作
  channel: 'qq',        // 可选，便于按通道筛选
  target: 'group:12345' // 可选，目标会话
}
```

- `operator: 'human'` 是“人工”chip 的唯一判据。
- 人工动作不写 `events.jsonl`，不算她的行为。
- 通道模块只调用共享的 `noteHuman()` 辅助函数，不直接拼日志行。

### 8.4 服务端 `/api/status` 的通用映射

现在返回：

```js
{ at, qq: { ...qq, login }, wx, her, log: [...] }
```

改为在保留旧键的同时增加：

```js
{
  at,
  qq: { ...qq, login: qqLogin },
  wx, her, log,
  channels: { qq: { ...qq, login: qqLogin }, wx }
}
```

- `channels` 是 `id → 状态对象` 的映射；外壳和总览只读这个映射。
- 旧键保留一个版本，避免其他调用方（测试、脚本）立刻断掉。
- 新通道只需在 `server.mjs` 里加一个采集函数并放进 `channels`，不需要改前端外壳。
- 不新增 `/api/channels`；一个 `/api/status` 足够。

## 9. 数据流、轮询与状态

| 页面 | 轮询 | 说明 |
| --- | --- | --- |
| 外壳 | 共享 `/api/status` 30 秒、`/notify` 60 秒 | 只在页面可见时跑；用于侧栏状态点和标题条 |
| 她 · 今天 | 60 秒重读 | `inbox` 只在进入页面读；`/notify` 由外壳管 |
| 她 · 记忆 | 无 | 手动读取 / 切日期 |
| 她 · 成长 | 无 | 进入页面读一次 |
| B 站 · 今天 | 无自动轮询 | `/comment` 是外部副作用，只在进入 / 点刷新时调 |
| B 站 · 足迹 | 无 | 手动刷新 / 切天数 |
| B 站 · 管理 | 无 | 保存后回读 |
| 通道 · 总览 | 共享 `/api/status` 3 秒 | 只在页面可见时跑 |
| 通道 · QQ | 共享 `/api/status` 3 秒 | 消息手动刷新；掉线提醒由服务端循环管 |
| 通道 · 微信 | 共享 `/api/status` 3 秒 + 画面约 1 秒一帧 | 画面只在页面可见且微信在跑时跑 |
| 系统 · 日志 | 无 | 手动读取 |
| 系统 · 数据 | 无 | 手动操作 |

- `/api/status` 由外壳维护一个共享轮询器：默认 30 秒；任何一个通道页可见时临时改成 3 秒，离开后恢复 30 秒。页面不各自再起一个 `/api/status` 定时器。

错误处理：

- `fish()` 返回的 `ok` 只表示 HTTP 成功；业务结论在 `data.ok` / `data.code`，页面分开展示。
- 读失败：`读不到：<code>（上游 N）`；写失败：`没成：<原因>（上游 N）`。
- 任何卡片失败只影响本卡，不整页白屏。
- 每个会写文件的读接口（`/inbox`、`/paths`）保持现有同源校验；页面不自动轮询它们。

## 10. 安全边界

- 浏览器仍然只访问 `127.0.0.1:8788`；鱼侧只走 `/api/fish/*` BFF。
- Host 校验、写请求 Origin 校验、`Sec-Fetch-Site: cross-site` 拒绝、CSP、`nosniff` 全部保留。
- 静态文件仍只服务 `index.html` 与 `assets/`；新增 `theme-boot.js` 也在 `assets/` 下，不扩大白名单。

- 以她身份发送 / 打字 / 回车 / Esc 必须二次确认，服务端记录 `operator: 'human'`；不写事件流。点按只记日志，不冒充她说话。
- cookie / token 不写日志、不进页面；B 站 cookie 输入框永远不回显。
- 危险操作（恢复、重置、清空日志、清理帧存档、解冻）保留输入确认词或二次确认；前端确认不是安全边界，上游 `confirm` 字面量必须原样传递。
- 不新增外部网络请求；不加载网络字体、图标、脚本。

## 11. 代码结构与拆分

见 8.5。补充约定：

- `app.js` 只做外壳：主题、路由、一级 / 二级注册、外壳轮询、`hashchange`。不包含任何业务页面逻辑。

- 每个通道模块自己管理消息 / 画面 / 范围；`leave()` 必须停帧循环。

- 样式集中在 `theme.css`（变量）和 `app.css`（组件）；不写内联颜色，不写页面专属的全局选择器。
- 页面专属样式用页面根节点上的 `data-page` 作用域，例如 `[data-page="bili-today"] .timeline`。

## 15. 风险与回滚

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 外壳重构影响所有页面 | 页面暂时不可用 | P0 先做“旧内容新外壳”，逐页替换；旧文件保留 |
| 主题首屏闪烁 | 体验差 | `theme-boot.js` 同步设置 `data-theme`；CSS 变量在首屏前生效 |
| 衬线字体在 Windows / WSL 不一致 | 视觉不统一 | 使用系统字体回退栈；在两种环境各看一次 |
| 通道拆分遗漏功能 | 掉线处理回归 | 4.5 覆盖表逐项验收；旧 `channels.js` 保留到 P5 验收后的下一个版本 |
| 配置搬家让人找不到 | 用户困惑 | 系统 · 设置顶部“配置搬家”说明 + 直达链接；不删除旧键 |
| 窄屏交互窗太窄 | 无法操作 | 画面最大高度 50vh；按钮换行；必要时上下堆叠 |
| 测试断言大改 | CI 失败 | P0 同步更新导航 / 注册表测试；不跳过真实断言 |
| 人工动作误标成她的行为 | 数据污染 | 统一 `operator: 'human'`；写事件流的路径不经过工作台 |
| 过度抽象 | 代码复杂 | 只抽共享辅助；不做插件市场、动态加载、通用组件库 |

回滚：

- 每个阶段独立提交，`git revert` 即可回到上一阶段。
- P0 回滚恢复旧 `index.html` / `app.js` / `app.css`；旧页面文件仍在。
- P3 回滚回到 P2 的提交：旧 `channels.js` 与 `legacy-channels.js` 仍在，不需要手工改 `index.html`；`/api/status` 的 `channels` 映射可保留（旧键未变）。
- 全流程不改 `~/.dsh-fish`、`watch.json`、`frames/`、`hold.json`，回滚无数据影响。
- 不 force push、不重写历史、不清理工作区。
