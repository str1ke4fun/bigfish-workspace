# 微信收藏表情：索引、检索与安全发送方案

状态：M1（只读索引）已实现并合并到 main；M2（发送）未实现

日期：2026-11-03

范围：`src/dsh-wx`（收藏表情的索引与工具）；`src/dsh-fish` 只加提示词层的最小接口

关联：`src/dsh-wx/NEXT-STAGE.md`；本文 §2 的结论来自 2026-11-03 的实机探针（测试账号 `cat不到flag的cat`）

## 0. 结论摘要

| # | 决策 | 落点 |

| 1 | 只做**收藏表情**（心形页签），不扩 emoji 面板 | §1 |
| 2 | 第一阶段只做**只读索引**：扫描 + 列表 + 检索，不做发送、不做自动收藏 | §8 |
| 3 | 身份主键用 **pHash**；视觉描述和 OCR 只作提示，不当作事实 | §4 |

## 1. 目标与非目标

### 1.1 目标

1. **她知道收藏里有什么**：每张收藏表情有可检索的描述、图上文字和标签。
2. **能按意图找**：一句关键词（如“牛 收到”“打劫”），能返回少量候选，而不是把整个面板塞给她。
3. **身份稳定**：收藏顺序变化、新增、删除、重启客户端之后，仍能通过 pHash 认回同一张。
4. **增量维护**：打开面板时顺手扫描；只描述新出现的格子，不重复烧算力。
5. **可安全发送**（第二阶段）：按索引 id 点格子，点击前校验会话与面板布局，点击后校验消息区回执。
6. **可采集**（第三阶段）：优先从收到的表情右键 `Add Sticker`；关键词搜索采集单独开关。

### 1.2 非目标

- 不做 emoji 面板。内置 emoji 已经可以用 `[Smile]` 这类短码经 `wx_type` + `wx_send` 完成，不重复造轮子。
- 不做微信协议逆向，不读加密的 `emoticon.db`，不尝试解密 `business/emoticon/Persist/` 下的 blob。
- 不自动给所有会话发表情；不改变现有发送许可、频率和任务板约束。
- 不把索引写进她的成长事件流，也不把表情描述当成人设或记忆。
- 不删除、不重排历史消息和台账。
- 第一阶段不做任何 UI 点击式发送；扫描本身只打开/关闭表情面板。

## 2. 调研结论（实机证据）

### 2.1 面板与数据形态

- 工具栏 `Send Sticker(Alt+E)` 打开一个 485x485 的弹窗（实测逻辑坐标 `(363,247)`）。底部三个页签：搜索、All Stickers（内置 emoji）、心形（收藏表情）。
- 面板是独立的 X 工具窗：`WM_CLASS=wechat`、`WM_NAME` 为空、`_NET_WM_WINDOW_TYPE_UTILITY`，尺寸 485x485。`xdotool search --class '^wechat$'` 能按尺寸认出来，`import -window <id>` 能直接截图，不需要 CU；`Alt+E` 只负责打开，收起要点输入栏的表情按钮。
- 收藏表情页签实测 7 张（探针前 6 张，测试新增 1 张），**5 列网格**，格子 84x84，横向间距 92px，纵向间距 84px，首格 `(16,14)`；第二行 2 张。
- 无障碍树里：
  - All Stickers 页签暴露 24x24、44px 间距的无标签 `push button ""`；
  - **收藏表情页签一个格子都不暴露**；
  - 搜索页签同样不暴露输入框和结果。
- 消息区所有自定义表情的 label 都是 `Animated Stickers`；侧栏预览统一是 `[Sticker]`。同一个会话里发两张不同表情，台账看到的文本完全相同。
- 本地缓存：`~/xwechat_files/<wxid>/business/emoticon/Persist/` 是哈希命名的加密 blob；`emoticon.db` 加密；内置 emoji 是明文 `resource/emoticon_webp/<编号>_<中文名>.webp`。**不能靠读盘建自定义表情索引。**

### 2.2 视觉与文字识别

同一个模型端点（`ep-20261020175544-mb2wc`）的三组对照：

| 输入 | 结果 |
|---|---|
| 60px 面板缩略图（直接看） | 把卡通奶牛认成“白猫” |
| 同一格子放大 4 倍 | 认出“奶牛”，但漏掉图上“收到” |
| 聊天里 132px 气泡放大 3 倍 | “卡通奶牛、举爪敬礼、收到”全部正确 |

本地 tesseract（`wx_ocr` 同款）在面板格子和聊天气泡上均失败：格子输出 `<`、`} .`，气泡上的“收到”读成 `} .`。**文字也读不出来，不能把 OCR 当高置信锚点。**

结论：

- 识别准确率强依赖分辨率与来源；面板缩略图不可靠，气泡/预览大图明显更好。
- 图上文字和多模态描述都需要视觉模型；本地 OCR 只能当兜底，不能当主路径。
- 因此描述必须带 `confidence` 和 `source`（panel / preview / bubble / manual），检索时按置信度加权，展示时标明不确定。

### 2.3 操作流程

- **点收藏表情 = 立即发送**，无确认、无“仅插入”。实测向测试号发送了两次“收到”牛。
- **收到的表情**：右键 → 菜单含 `Add Sticker`；点击后收藏数 6 → 7，新表情排在第一位。
- **自己发出的表情**：右键菜单同样含 `Add Sticker`（另有 `Recall`）。
- **搜索结果**：面板放大镜 → `Search Stickers` → 输入“猫” → 返回多行猫表情（在线库）。**点结果 = 直接发送到当前会话**（实测向测试号发了一张白猫）；随后右键该消息 → `Add Sticker` 可收藏。
- 收藏项右键只有 `Move to Front` / `Delete`；`Delete` 立即生效，无二次确认。
- 搜索结果右键只弹出一个 200x200 的预览大图，未发现 “Add” 按钮。

### 2.4 运行时风险

- 微信 Linux 的 `Ctrl+L` 是锁定快捷键，触发后只能手机解锁；本轮探针曾因此把客户端锁住。`Escape` 也曾弹出 `Log out?` 确认框。实现与测试都必须避开这两个键。
- 表情点击没有二次确认，因此发送工具不能“先点了再说”。

## 3. 总体设计

### 3.1 组件

| 组件 | 职责 | 建议位置 |
|---|---|---|
| 扫描器 | 打开收藏页签、截图、切格、算 pHash、增量更新 | `lib/sticker-scan.js` |
| 索引存储 | 读写 `~/.dsh-wx/stickers/index.json`；原子替换 | `lib/sticker-index.js` |
| 描述器 | 对新格子生成文字/描述/标签；可插拔 | `lib/sticker-describe.js` + 可选 sidecar |
| 检索 | 关键词 → 候选卡片；不做发送 | `lib/sticker-query.js` |
| 发送（阶段二） | 按 id 定位、校验、点击、回执 | `lib/sticker-send.js` |
| 采集（阶段三） | 右键 `Add Sticker`；搜索采集 | `lib/sticker-collect.js` |
| 工具注册 | `wx_sticker_list` / `wx_sticker_find` 等 | `lib/index.js` |

零依赖约束不变：只用 Node 内置模块 + 现有 `wx.sh`（`import` / `convert` / `xdotool` / AT-SPI）。

### 3.2 数据流

```
Alt+E → 收藏页签 → 截图(485x485)
  → 切格(5列) → 每格 pHash + 缩略图
  → 与 index.json 对齐（hamming 距离）
  → 新格子进入描述队列 → 视觉/人工描述
  → index.json 原子写回
  → wx_sticker_list / wx_sticker_find 读取
  → （阶段二）wx_sticker_send 按 id 点击 + 回执
```

### 3.3 存储位置与生命周期

- 目录：`~/.dsh-wx/stickers/`，权限 `0700`；内含 `index.json`、`thumbs/<id>.png`。
- 索引是**派生缓存**：损坏或丢失时可从面板重扫重建；不参与归档，不写事件流。
- 缩略图只存表情本身，不存聊天区域；不保存会话名、联系人、消息正文。
- 描述生成若调用外部模型，只上传单张表情裁剪图，不上传整屏。

## 4. 索引模型

### 4.1 条目

```json
{
  "v": 1,
  "panel": { "w": 485, "h": 485, "cols": 5, "cell": 84, "pitchX": 92, "pitchY": 84, "firstX": 16, "firstY": 14 },
  "entries": [
    {
      "id": "st_9f3a1c2b7d4e5f60",
      "pHash": "c3a5...",
      "thumb": "thumbs/st_9f3a1c2b7d4e5f60.png",
      "pos": { "row": 0, "col": 0, "order": 0 },
      "text": "收到",
      "textConf": "medium",
      "desc": "卡通奶牛，举爪敬礼",
      "tags": ["牛", "收到", "敬礼"],
      "descConf": "medium",
      "source": "bubble",
      "firstSeen": "2026-11-03T16:44:00+08:00",
      "lastSeen": "2026-11-03T16:52:00+08:00",
      "stale": false
    }
  ]
}
```

字段说明：

- `id`：由 pHash 与首次发现时间生成，稳定不变；发送工具只认 `id`，不认位置。
- `pHash`：64 位 dHash，格图先归一化为 96x96 灰度。相同表情 hamming ≤ 6 视为同一张；同时保留裁剪图的 sha256 做精确匹配。
- `pos`：**最近一次扫描**的位置，仅用于显示和发送定位；每次发送前必须重新扫描核对。
- `text` / `desc` / `tags`：描述器产物，带置信度；可为空。
- `source`：描述所用的图源，`panel`（最低）、`preview`（200x200）、`bubble`（聊天气泡）、`manual`。
- `stale`：最近一次扫描没看到，但保留条目以便重新认回；不自动删除。

### 4.2 顺序与去重

- 微信会把新收藏放到第一位；使用/右键 `Move to Front` 也可能改变顺序。**位置不是身份**，每次扫描用 pHash 重新绑定。
- 扫描视口内重叠去重：滚动翻页时保留上一屏最后一行做重叠对齐，和台账的做法一致。
- 收藏删除：下一次扫描找不到对应 pHash，标 `stale`；不立刻删条目，保留 30 天后清理。

### 4.3 描述器（可插拔）

接口：

```js
describe({ png, source }) -> { text, textConf, desc, tags, descConf }
```

实现顺序：

1. **本地 VLM 侧车**（推荐，符合“不接云端视觉 API”）：与 `sidecar/` 的向量侧车同构，独立进程、本机地址、超时与熔断；模型建议 Qwen2.5-VL-3B/7B Instruct（int4），RTX 5060 8GB 可跑。当前机器未安装，需要单独部署。
2. **人工/代理标签**：阶段一没有 VLM 时，索引照样可用；新格子先只有 pHash 和缩略图，由人工或会话中的代理补标签。
3. **现有模型端点**（可选开关，非默认）：只上传单张裁剪图；它不是新的云视觉 API，但图片会离开本机，默认关闭。

描述提示词要求模型只描述确定的内容，看不清就写“看不清”，并分别输出图上文字、主体、动作、标签；不得猜测聊天语境。

## 5. 扫描流程（阶段一）

1. **前置检查**：当前微信窗口存在且未锁定；面板未打开或已打开都可处理。
2. **打开收藏页签**：`Alt+E` 打开面板；若落在其它页签，点击底部心形图标（面板内 `139,463`）。用截图校验页签（收藏页签没有搜索框、没有 `All Stickers` 标题、格子是自定义图片）。
3. **几何校验**：窗口必须是 485x485（或记录当前尺寸）；若尺寸/DPI 变化，先重算网格，不沿用旧参数。
4. **切格**：按实测网格 5 列、84x84 格子、横向间距 92、纵向间距 84、首格 `(16,14)`；每格先算内容占比，空白格不算条目。
5. **逐格处理**：裁剪 → 缩略图落盘 → 64 位 dHash → 与条目匹配（先精确 sha256，再 hamming）。
6. **增量描述**：新条目或 `descConf` 为空的条目进入队列；阶段一由人工/代理用 `wx_sticker_tag` 补标签，每轮不烧视觉算力。
7. **写回**：原子写 `index.json`（临时文件 + rename）；更新 `lastSeen`，未见到的标 `stale`。
8. **关闭面板**：点输入栏最左边的表情按钮切换收起（`Alt+E` 不能当开关用）；不用 `Escape`。
9. **返回摘要**：新增/更新/失效数量、耗时、失败原因。

扫描本身不点击任何表情格子，只点击心形页签、输入栏表情按钮和面板内空白区。

## 6. 检索（阶段一）

### 6.1 工具

- `wx_sticker_scan({})`：扫描收藏页签、更新索引；只点心形页签，不点任何表情格；完成后关面板并返回新增/认回/未见数量。
- `wx_sticker_list({ limit?, cursor? })`：按最近使用/最近发现排序，返回紧凑列表：`id`、`tags`、`text`、`desc`、`descConf`、`lastSeen`。不含图片。
- `wx_sticker_find({ query, limit? })`：中文二元组 + 标签/描述/文字匹配；返回最多 5 个候选，带匹配原因和置信度，格式沿用检索卡片的做法。
- `wx_sticker_tag({ id, text?, desc?, tags?, textConf?, descConf? })`：人工/代理补标签，只写派生索引，不改微信收藏。
- 没有命中时返回“没有找到”，不编造。

### 6.2 展示规则

- `descConf` 为 `low` 或 `source=panel` 时标注低置信，避免她笃定地说“这是猫”。
- 描述与文字冲突时（例如标签写“猫”、图上写“收到”），两个都展示，不合并成一个结论。
- 检索结果只是候选；是否发送由她决定，工具不自动发。

## 7. 发送（阶段二）

### 7.1 前置条件

- 目标会话与当前打开会话一致；不一致时先按现有 `sendToChat` 的方式切换并确认。
- 面板几何与索引快照一致；不一致则先重扫，不盲点。
- 目标 `id` 在索引中且 `stale=false`。
- 发送许可、频率、任务绑定沿用现有 `wx_send` 的门禁。

### 7.2 步骤

1. 打开面板并切到收藏页签。
2. 按 `pos` 裁剪目标格，计算 pHash；与 `id` 的 pHash 距离超过阈值（> 6）就中止，重新扫描后重试一次。
3. 点击格子中心（面板用截图坐标 + 窗口原点；无障碍树元素用 `scale.js` 的 ×1.0417）。
4. 校验回执：消息区新增一行 `Animated Stickers`；截取新气泡，pHash 与目标 `id` 比对。
5. 成功才写出站台账（`kind=sticker`，附 `stickerId`）；失败不写“已发送”。
6. 每步失败都保留现场截图路径和原因，不自动重试超过一次。

### 7.3 禁止项

- 面板布局异常、窗口尺寸变化、当前会话不明时**不点**。
- 不通过固定偏移盲点“猜测位置”；位置必须由本次扫描确认。
- 不在群聊或非白名单会话里做发送测试。

## 8. 采集（阶段三）

### 8.1 从收到的表情收藏（首选）

1. 在消息区定位 label 为 `Animated Stickers` 的行，取其 frame 中心。
2. 右键 → 等待弹出菜单窗口（约 169x231）→ 截图识别 `Add Sticker` 项（不用固定偏移）。
3. 点击 `Add Sticker`；重新扫描收藏页，确认第一格 pHash 与新表情气泡一致。
4. 只增加收藏，不发送任何消息。

### 8.2 关键词搜索采集（需单独开关）

1. 打开搜索页签，输入关键词，截图结果网格。
2. 结果无标签，需视觉/人工挑选；点击结果会**立即发送到当前会话**。
3. 因此只允许在白名单会话（如测试号）里执行；发送后右键该消息 → `Add Sticker`。
4. 默认关闭；开启前必须由用户明确授权目标会话。

### 8.3 删除

- 只有用户明确指名删除时才操作；删除前展示缩略图、`id`、位置和后果，取得当次批准。
- 删除后重新扫描并标 `stale`，不手工改历史。

## 9. 安全、隐私与约束

- **不新增云端视觉 API**；默认不上传图片。启用任何外部描述器都必须由用户显式配置。
- 索引只存表情缩略图与描述，不存聊天正文、联系人和时间线。
- 不写 `events.jsonl`；索引不是记忆，删除索引不影响她的历史。
- 遵守 `src/dsh-fish/AGENTS.md`：零依赖、不写人设、事件流只追加。
- 危险操作审批：删除收藏、批量采集、修改发送白名单都必须单独取得当次批准。
- 键位黑名单：`Ctrl+L`（锁定）、`Escape`（可能弹登出确认）；关闭弹窗一律点击安全空白区。
- 锁屏/登出状态下扫描必须直接返回“客户端不可用”，不尝试重启或绕过。

## 10. 测试计划

### 10.1 单元测试（不启动 GUI）

- 网格切分：用**合成图**（纯色格子 + 文本）验证 5 列、行距、首格偏移；不提交含个人表情的截图。
- pHash：同图不同缩放/压缩距离 ≤ 阈值；不同图距离 > 阈值；顺序变化后仍能匹配。
- 索引：新增、更新、`stale`、重建、原子写、坏文件回退。
